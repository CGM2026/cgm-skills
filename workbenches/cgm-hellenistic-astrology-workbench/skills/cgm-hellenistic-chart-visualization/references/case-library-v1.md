# 本地案例库与 Agent 协作

## 入口与存储

使用套件配置的 Python 调用本 skill 的 `scripts/library_cli.py`。全局参数 `--library <目录>` 放在子命令之前；工作区默认目录 `case-library`。安装 skill 的目录不能充当案例库。两个 skill 必须同级安装。首次环境与方法配置由计算成员自行完成。使用非当前工作区的配置时加全局参数 `--settings <settings.json>`，使网页保存的新盘默认与计算入口共享同一文件。

`open` 自动启动隐藏的本机服务，默认 `127.0.0.1:4860`，已启动则复用；端口属于另一案例库时停止并提示改用 `--port`。不注册开机启动。关机后让 Agent 再次打开即可恢复服务。页面地址只在这台电脑有效。

库目录中 `cases.sqlite3` 是权威数据；`assets/` 存共用字体等资源。SQLite 使用 WAL、FULL 同步、事务提交、压缩记录与内容哈希去重。HTML 由模板和数据即时装配，非逐个常驻文件。旧 HTML 导入后仍保留，后续库中编辑不反向同步旧文件；避免两边继续编辑。

保存旧页面前先确认它显示“已保存”，再导入。同一路径重复 import 返回已有 view，不自动覆盖库中后续编辑。导入只读取 HTML 已归档状态，不能自动提取另一个浏览器尚未同步的私有草稿。

## 创建、检索、打开

```text
<python> library_cli.py --library <库> list --query <姓名片段>
<python> library_cli.py --library <库> import <同一案例本命.html> <行运.html> <其他盘式.html>
<python> library_cli.py --library <库> create --facts <本命v4.json>
<python> library_cli.py --library <库> create --facts <v4.json> --mode natal
<python> library_cli.py --library <库> create --facts <本命v4.json> --mode zodiacal-releasing --case-id <同一本命case_id>
<python> library_cli.py --library <库> create --facts <行运v4.json> --mode transit --natal-view <本命view_id>
<python> library_cli.py --library <库> create --facts <本命v4.json> --mode return --natal-view <本命view_id> --from-time <ISO时刻>
<python> library_cli.py --library <库> open --view <view_id>
```

不指定 `--mode` 时默认 `complete`，一次创建六盘式并返回每种 view ID；重复创建复用已有案例并补齐缺失盘式，不复制笔记。`--from-time` 可指定有时区的创建参考时刻，默认当前时间。行运使用该时刻，返照寻找此后出生地的下一次太阳返照；三种大运保存计算事实和口径，页面按需生成当前起运表。已有六盘式模板时复用共享模板，计算新事实及最多42组可用显示数据；空库首次调用既有渲染器建立模板。批量测试可用 `--template-library <六盘式模板库>` 初始化独立库，不复制模板案例的记录。

显式单盘模式：`natal`、`transit`、`return`、`decennials`、`firdaria`、`zodiacal-releasing`，用于补建与专项维护。新地点等专项返照流程仍使用既有计算/渲染器，完成后 import。创建时暂存渲染产物，入库后清理临时文件，不重复保留字体包。

## 宽屏与宿主浏览器

工作页每次打开在可用宽度至少1180px时自动左右并排：左侧标题、排盘设置、完整轮盘及图示；右侧六盘式导航、保留卡片标签与一张当前卡片。点击点位直接进入右侧卡片，选择另一标签只显示对应卡片。窄屏默认上下排列。工具栏手型图标下方的简洁布局图标点击后直接切换为另一种排列，不弹出菜单、不读写布局偏好；刷新或切换盘式后恢复自动。PNG和SVG导出可在弹窗选择横图或竖图，默认选择竖图，不保存偏好。两种布局均只保留当前选择的正文与盘面，清除操作控件、内部滚动限制和空侧栏，按清理后内容自然裁剪；横图无右侧正文时保留左栏尺寸与位置，从右边裁掉空栏，不扩宽左栏或重新居中轮盘；个人标识置于全部内容之后，横贯整图。

宿主提供大页面与可折叠悬浮聊天时，本页沿用同一HTTP地址、数据库和保存接口，可适配得到的实际宽度。skill不承诺控制宿主全屏或聊天悬浮开关。打开顺序固定为 `open` 确认/启动服务，再用返回URL；页面渲染失败时检查该URL与 `/health`，不能仅重开本地HTML路径，也不另起正式库端口绕过问题。

盘式切换不使用选项卡及下划线。标题行左侧为当前完整盘名，右侧为“更多盘式”，两者使用同一较大字号，右侧颜色更淡。弹窗读取该案例已有页面链接，完整展示本命盘、行运盘、返照盘、十年九月运盘、法达星限盘、黄道释放盘；新增盘式自动加入同一列表，不把尚未制作的盘式作为可切换页面。当前盘式有明确标记，选择其他盘式沿用保存确认、冲突与草稿保护逻辑。关闭按钮和 Escape 可退出弹窗。下方卡片选项卡沿用原样。仅当竖排且没有卡片选项卡时，在盘式标题行上方显示分隔线；出现选项卡即隐藏，横排不显示该线。

盘式标题行与相邻内容使用约8px的紧凑间距。宽屏的盘面显示开关移动到左上方排盘设置下方，图式或专用入口在前，界、签点、虚点、小行星随后纵向左对齐；底部保留签点图例，轮盘铺满左侧可用宽度，不以窗口高度限制尺寸，盘面上方不额外留白。移动既有 DOM 控件，不复制状态或事件。窄屏恢复底部排列，进入笔记图层仍隐藏并锁定这些开关；竖图导出恢复纵向布局，横图导出沿用左右布局并移除操作控件。

## 只读相关字段，少读 HTML

```text
<python> library_cli.py --library <库> notes --view <ID>
<python> library_cli.py --library <库> objects --view <ID>
<python> library_cli.py --library <库> objects --view <ID> --start <起运键> --path 0,1
<python> library_cli.py --library <库> note-put --view <ID> --input <笔记.json>
<python> library_cli.py --library <库> note-put --view <ID> --input <笔记.json> --expected-revision <读取时版本>
<python> library_cli.py --library <库> record-put --view <ID> --input <记录.json> --expected-revision <读取时版本>
```

`notes` 返回该盘式的图层、关联笔记、案例记录和未完成编辑草稿。`objects` 对推运盘返回当前层对象键；`--path` 是逐层的零起始索引，空路径列大运/L1，`0` 列第一大运的年限/L2，以此类推。对象键原样传入，不手拼跨盘对象。轮盘普通对象可用 `sun`、`moon` 等实际键；未列出的特殊对象通过页面选择后读取笔记。

新笔记输入：`{"layer_name":"研究笔记","title":"标题","text":"正文","objects":["sun"]}`。已有图层改用 `layer_id`；修改已有笔记另带 `id` 和 expected-revision。新行运/返照图层还需 `transit_time` 固定时刻。Agent 负责依据用户资料整理文字，不能伪造反馈、推算吉凶或跨盘引用。

`transit_time` 可输入 ISO 时刻；接口按该 view 的当地时区统一后写入页面使用的格式：行运为 `YYYY-MM-DDTHH:MM`，返照保留六位小数秒。不要绕过接口直接写入另一种时间格式。

档案输入：`{"title":"第一次记录","date":"2026-09-29","analysis":"分析","feedback":"反馈"}`；日期可空，分析/反馈至少一项。编辑另带记录 `id`。不同字段的并发修改可自动合并；同一字段改成不同内容拒绝覆盖。冲突时先读最新状态和保留草稿，核对具体文本后用新版本再写，不盲目重试覆盖。

## 统一内容与卡片规范

本规范同时约束手动编辑、Agent 快速添加、批量模拟数据及后续页面维护；现有模板与交互组件是唯一展示入口。

- 笔记属于当前 view 的笔记图层，存入 `relations` 中的 `id`、`title`、`text`、`objects` 等字段。Agent 先读取 `notes` 和 `objects`，再使用 `note-put`；档案使用 `record-put`。不要用旧的图层说明字段 `layer.note` 代替笔记，也不要直接拼接正文到 HTML 或页面容器。
- 写入笔记只创建或更新记录，不自动把内容摆到原始星盘下方。进入所属笔记图层后，以现有笔记选项卡查看、编辑和标记；原始图层通过对象详情的关联笔记入口查阅。
- 用户明确选择“放为卡片”后，由共用 `ChartRelationNotes.dock(layerId,noteId)` 调用 `ChartDock` 创建展示卡片；笔记图层内也提供同一入口，成功后返回原始星盘。笔记原记录及所属图层保留。Agent 需要展示时操作该入口，不自行创建另一套 DOM、卡片列表或切换规则。
- 笔记卡片与行运时刻、运程表、对象详情、档案卡片同属一个 `docked-tabs` 选项卡组。横排、竖排都只显示当前选项卡的正文；未选择放为卡片的笔记不得作为分隔线下的常驻内容。沿用现有卡片数量限制、关闭、键盘切换和导出规则。
- 旧 `layer.note` 文字兼容为该图层内的一条旧笔记，不丢弃原文，不自动下放；后续写回采用结构化笔记。旧笔记没有关联对象时保留这个事实，不虚构对象。
- 交付前检查记录确实在正确 view 的笔记图层内；原始图层没有额外笔记段落；下放后与已有固定卡片并列，切换时只有一张卡片可见。验证共用入口，不以截图上的位置碰巧正确替代数据和交互检查。

## 页面保存与恢复

输入事件立即把当前编辑器草稿交给浏览器存储；停顿约 500ms 后提交到本机数据库。完整关联笔记/档案也自动更新，未满足标题等条件的内容作为可恢复草稿保存。刷新恢复正在编辑的窗口与文字。完成按钮负责结束编辑；“取消”不能理解为撤回已经自动保存的完整记录。

数据库确认后隐藏保存状态，不显示“已保存”；确认也包括未完成但已存档的编辑草稿。“仅保留草稿”表示数据库尚未确认。服务中断后保留页面，Agent 重新 `open` 启动服务，再刷新恢复并补存。不同标签页草稿分别备份；发现旧标签页积压草稿时由页面入口选择恢复，不静默覆盖。

两个页面修改同一内容时，HTTP 409 返回最新字段与版本，页面暂停自动重试并打开“核对两个版本”。按稳定记录 ID 合并独立修改，冲突项显示双方原文，可保留草稿、保留案例库版本或合并文字。保存核对结果前备份双方原文；其他页面再次修改时重新核对。恢复旧草稿走同一流程，避免恢复与重试循环。损坏的已存字段保留原文，`state.warnings` 提供原因与最近有效历史 ID；页面可通过 `/api/restore-entry` 携带最新版本恢复。

所有已知笔记、档案、编辑草稿结构在写入前校验；记录 ID 不得重复，关联对象必须是有效对象数组。新时段对象含 `caseId` 和 `viewId`，路径、起止边界、主管星必须与本盘计算时间表吻合。旧无归属的时段引用仅允许保留在原记录内，不作为跨案例复制入口；前端兼容匹配旧引用与本盘新引用。

离开/切盘前会补存；未保存时有明确状态和保留草稿入口。正常运行无需每次让 Agent 执行保存。浏览器草稿与数据库均失败时必须保留当前页面。无法承诺断电、磁盘损坏或操作系统清理之前尚未确认的输入永不丢失。

Agent 写入后，空闲页面约 3 秒检查新版本并刷新；编辑器打开时推迟，避免打断输入。页面和 Agent 共用同一数据库。每种盘式的 notes/records/drafts 都按 view ID 独立。

## 备份、恢复、导出

```text
<python> library_cli.py --library <库> backup --output <备份.sqlite3>
<python> library_cli.py --library <库> history --view <ID>
<python> library_cli.py --library <库> restore-entry --view <ID> --history-id <历史ID> --expected-revision <最新版本>
<python> library_cli.py --library <库> export --view <ID> --format json --output <记录.json>
<python> library_cli.py --library <库> import-records --view <ID> --input <记录.json> --expected-revision <最新版本>
<python> library_cli.py --library <库> export --view <ID> --format html --output <分享.html>
<python> library_cli.py --library <库> stats
```

数据库 backup 使用在线一致性快照。完整搬家需同时保留 `assets/`、两 skill 的版本和 Python 依赖；不要只复制正在写入的 sqlite 主文件。恢复时关闭对应库服务，把备份用于新的库目录并复制共用 assets，确认后打开。历史每盘最近 100 次字段修改、全库约 20MB 上限；恢复写入也保留被替换值。

JSON 导入要求同一案例、同一盘式和相同排盘事实，附当前版本，避免串档。独立 HTML 为便携阅读副本，包含当前案例已有盘式、字体子集、时间表及保存记录；可阅读并导出图片，不支持编辑、保存或重新计算。内容以生成时刻为准，更新由 Agent 在电脑端完成后重新导出。HTML 与 JSON 含完整出生资料、计算快照和记录；图片的匿名选项不会删除这些结构化资料。分享资料副本前需核对其中全部内容。日常保存无需导出 HTML。图片导出沿用页内预览，隐藏保存图标与模式切换文字。工作页 SVG 将 PNG 图像放入 SVG 容器，不是可逐个编辑盘面对象的纯矢量图。

记录导入在一个事务中校验版本并覆盖文件包含的字段，文件未包含的字段保留；空字段快照为合法无修改操作，多于100个字段仍可原子导入。单字段上限2MB，请求上限32MB，容纳字段前后值和 JSON 转义后的请求；导出和导入采用同一字段约束。

长正文图片逐段捕获，按文字行与图块边界拆成等宽的多张图，保留字号、顺序和全文。每张带页号并可分别下载 PNG/SVG，整组下载为 ZIP；短内容仍为一张图。个人标识沿用原样式，只放在全部正文之后，即最后一张底部。横竖布局、匿名、当前卡片和空侧栏裁剪规则不变；生成失败必须显示原因，禁止将空画布作为成功预览。

## 体积与版本

共享字体约 84MB 是一次性开销；增加案例主要增加压缩事实和文字。图片附件、大量独立 HTML 导出和另存备份不在轻量案例体积承诺内。容量以 `stats` 实测，不能把当前单个样本直接说成已完成数千案例压力测试。

时间表由对应计算器当前版本重建，原始 basis 和事实保留。更改算法前比较旧输出；保留两 skill 的版本以便复现。本版尚未提供自动算法版本迁移。旧 HTML 专项查询脚本需要在临时工作页中运行后导入，不能向库 URL 直接调用旧的文件写回接口。

每个笔记图层最多30条；达到上限仍可编辑/删除，旧超限记录保留。Agent批量添加也遵守同一限制，不能通过导入或合并绕过。笔记图层外部只显示最多三个已打开笔记标签，按首次打开顺序移除最早标签；“全部笔记”弹窗选中后通过“显示此笔记”显示，放为卡片另行操作。详见工作页规范。


## 档案阅读与编辑

记录汇总、汇总分析、汇总反馈均使用最多三行的摘要；进入记录后显示完整正文。返回列表位于窗口右上角关闭按钮旁，返回保留原查看方式与滚动位置；关闭退出整个档案。窗口标题在滚动时保持可见。分析与反馈独立折叠，打开记录时已有内容默认展开、空栏默认收起；手动打开后可继续输入。文本框随内容增高，全文使用档案窗口滚动。已有记录的删除按钮为左下方红色文字。滚动条沿用页面暖灰褐色细线风格。

折叠入口在右侧显示操作文字加符号：收起为“展开 +”，打开为“折叠 −”；沿用小号淡色字体，点击整行切换。

操作文字用统一 12px 字号、24px 固定文字列左对齐，符号为独立 16px 列，列间距 8px；展开与折叠切换不改变各列位置。


档案列表的标题、查看方式与底部操作栏保持可见，仅中间记录区域滚动；新增记录与放到下方随时可用。成功放置卡片后自动关闭窗口；无可展示内容等失败提示仍留在窗口内。占星横向布局使用「显示在右侧」入口。进入记录再返回时恢复列表位置；记录编辑仍使用窗口滚动以阅读全文。


记录汇总、汇总分析、汇总反馈均显示逐条勾选入口，未选中时放到下方停用。三种模式各自保留选择；分析/反馈模式只列含对应正文的记录，卡片仅包含所选记录的对应字段，不默认展示全部。不同摘录独立成卡片，原记录修改后同步，删除或正文清空后移除失效内容。成功放置后关闭窗口，底部操作栏继续固定。

## 案例备注入口

案例档案第一项为「案例备注」，直接编辑并自动保存。同案例跨盘式共用，独立于分析和反馈；详见 [案例备注](case-remarks.md)。
