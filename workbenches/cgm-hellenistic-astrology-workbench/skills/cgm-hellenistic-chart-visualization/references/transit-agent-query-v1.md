# Agent 行运查询结果规范 v1

用户只在 Agent 对话中提出查询。Agent 将自然语言整理成查询 JSON，运行 `scripts/run_transit_agent_query.py --page <行运 chart.html> --query <查询.json>`。计算程序负责黄经、宫位、顺逆、相位和时间边界；Agent 不得自行编造命中时间，也不得自行拼装结果 HTML。

## 查询输入

```json
{
  "title": "行运火星进入本命第九宫",
  "request_text": "找出过去十年火星在第九宫的时间",
  "start": "2016-09-27T00:00",
  "end": "2026-09-27T23:59",
  "conditions": [
    {"planet":"mars","kind":"position","motion":"any","scope":"house","value":9,"detail":"any"}
  ]
}
```

`methods` 可选；省略时取当前 HTML 档案中的原盘设置，若尚无设置则取原始输入。`visible_lots` 可选，仅允许当前盘面显示的本命签点。相位条件沿用计算器格式，例如 `{"planet":"mars","kind":"aspect","motion":"any","target_chart":"transit","target":"jupiter","aspect":"conjunction","orb":1}`。Agent 须在答复及结果中说清时间范围、行运／本命对象和容许度。若这些口径会明显改变结果且无法从用户话语与当前盘面确定，应先问用户。

## 写回格式

计算脚本将 `cgm.transit-query-result.v1` 记录追加到当前 HTML 的 `chart-transit-query-results-v1:{PAGE}` 档案字段。每条记录包含：查询标识、标题、原话、时间范围、时区与排盘口径、结构化条件、最多 40 段结果、是否截断、各条件单独命中数和计算精度。时间段用当地时间 `YYYY-MM-DDTHH:MM` 记录 `start` 与 `end`；单一时刻可令两者相同。已有记录不因新查询被覆盖。

## 弹窗版式

点击“行运查询”时，若尚无 Agent 查询记录，显示返回 Agent 的提示；有记录时打开最新查询结果弹窗，并可切换历史查询。弹窗固定顺序为标题与原话、时间范围与口径、条件列表、结果数量、时间段列表、底部分页。每页 5 段，至多 8 页；结果之间留白，不用分割线。零结果如实显示零结果，不延伸时间范围。

每段显示起止时间和满足的条件。可分别勾选“跳转行运盘”和“保存为卡片”，也可同时勾选，再按“确定”。跳转采用该段开始时刻并修改原盘行运时间。保存后的卡片标题只显示开始时刻，卡片本身只保留右上角关闭按钮。页面上仍可见的旧版结果卡片继续读取。新记录载入后首次打开页面，结果弹窗自动出现；此后可由“行运查询”按钮再次打开。

时间轴不是默认结果版式。只有某个特定研究问题确实适合并经过单独设计时，才可作为辅助视图出现。

## 当前案例库交互

进入行运原盘时按案例时区计算当下天象；笔记图层保留固定时刻。行运查询入口始终由用户主动打开，不因有新结果自动弹出。窗口保留向 Agent 提供时间范围和星象条件的提示，以及已有查询结果。结果提供「查看起始时刻」「保存为卡片」两个直接操作，替代复选框与确定按钮。不展示未说明取值时刻的偏差。多次查询使用紧凑选择框。以上规则优先于旧 HTML 的自动弹窗说明。
