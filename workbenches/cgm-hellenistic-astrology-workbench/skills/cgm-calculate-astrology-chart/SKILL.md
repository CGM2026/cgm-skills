# 独立七星排盘

## 任务

从时间、地点与方法设置生成可复现的盘面事实。计算层保持方法中立，计算七星、四轴以及带明确公式来源的福点与精神点，不生成任何具体解释技法的主链、代理星或判断。

## 沟通风格

采用套件统一的“亲切专业”风格：先用自然语言说明需要补充、配置或修正什么以及原因，再给技术字段；不连续抛出命令式问题，不把运行日志直接当作用户答复。亲切不等于模糊，时间、时区、黄道、岁差、界和宫位系统仍须精确核对。

## 必须读取

- 每次启动读取 [first-run-setup.md](references/first-run-setup.md)。
- 组装输入或排错读取 [input-contract.md](references/input-contract.md)。
- 输出给其他程序或 skill 时读取 [chart-facts-schema.md](references/chart-facts-schema.md)。

## 工作流

1. 检查工作区根目录 `.cgm-hellenistic-astrology/settings.json` 与 `runtime.json`；缺失时由本成员依照 [first-run-setup.md](references/first-run-setup.md) 完成一次性配置。计算与可视化两个成员即可独立使用。
2. 收集本地日期时间、经纬度与时区口径；读取已确认的个人默认。输入要求与默认不符时，说明具体差异并引导手动切换，不删去冲突字段或绕过检查生成另一种口径。
3. 运行 `scripts/calculate_chart.py --input <input.json> --settings <settings.json> --output <chart-facts.json>`；依据太阳真实地平高度判定昼夜，并按昼夜反转公式计算福点与精神点。
4. 运行 `scripts/validate_chart_output.py <chart-facts.json>`；通过后才交给下游 skill。
5. 向用户说明采用的时间、地点、黄道、岁差、界表、宫位系统和输出路径。

## 返照时刻查询

当可视化成员需要返照时刻时，由本计算成员运行 `scripts/calculate_return_query.py --natal-input <本命 chart-facts v4> --planet <星体英文键> --start <带时区 ISO 时刻> --end <带时区 ISO 时刻> --output <结果 JSON>`。目标取本命盘中该星体的黄经，沿用本命黄道、岁差、地心星历口径；传统七星读取已校验事实，天王、海王、冥王在本命儒略日以同一口径计算目标。逆行造成的逐次穿越分别输出，并保留微秒级求解时刻、当地时间和顺逆行。结果协议为 `cgm.return-query.v1`，不更改 `chart-facts` v4 的七星结构。可视化成员只接收结果和重新计算的完整盘面事实，不在 HTML 中求解黄经。

## 十年运计算工作稿

`scripts/calculate_decennials.py --natal-input <已校验的本命 chart-facts v4> --output <decennials.json>` 只计算时间段，不给运势吉凶解释。当前工作稿以昼生太阳、夜生月亮为默认起运星，也预计算传统七星分别起运的七套时间表；顺序按本命七星黄经依次轮转。大运每段固定 129 个月，年限按七星小限年数对应的月数（30、12、15、19、8、20、25）分配，年限内每 129 日另设一个月限，月限主管星按本命七星黄经顺序逐段推进；每个月限从其主管星起，按七星小限年数对应的日数分配日限。每月固定 30 天、每年固定 360 天，时间边界保存为 UTC 时刻，页面再按本命时区显示。这些是当前工作稿设置，产物标为 `working-draft`。129 日轮主逐轮推进参照瓦伦斯《选集》第六卷；后世增补提供另一种日数分配支系，现行组合不能表述为唯一的传统标准。每个完整 129 日轮次内部七星均分得日段；小运长度不同，所容纳的轮次数可少于七。

## 与案例库协作

`calculate_display_snapshots.py` 负责最多 42 种黄道/宫位/界表快照、三王星、月交点、莉莉丝、产前朔望与小行星的计算；不适用于当前纬度与时刻的宫制记录在 `unavailable_variants`，不伪造或替代宫头，也不连带阻断可用宫制。可视化包装器只将结果转换成绘图载荷。Windows 中文星历路径由独立进程使用相对路径读取，不改变调用进程工作目录。`calculate_transit_search.py` 接收已校验本命事实、输入及条件，负责行运查询。两者不依赖可视化代码。

可视化成员的案例库只保存事实、方法口径和记录，推运长表由本成员按需重建。`calculate_time_lords.calculate(facts, technique, start_sign=None)` 在指定 `start_sign`（0–11）时只返回黄道释放的一套起始星座时间表；未指定则保留旧的完整输出。法达口径不变。十年九月大运按既定 `nested_periods` 与 `civil_age.annotate_periods` 接口生成当前起运星时间表。真实生日年龄由 `civil_age.py` 统一输出；技法的 360 天或 365.25 天仅用于段长。

计算结果仍以本成员的校验、来源与 working-draft 标记为准。字体、颜色、笔记、数据库、浏览器自动保存与图片导出由可视化成员维护。

## 运行条件

使用 Python 3.11 及以上。先运行 [bootstrap_runtime.py](scripts/bootstrap_runtime.py) 检测 `pyswisseph` 与 IANA 时区数据；缺少依赖时必须先征得用户同意，再创建工作区隔离环境并安装，不修改全局 Python。计算采用 Swiss Ephemeris 的 Moshier 模式，不依赖 Astrologer 项目的目录、代码、服务或运行状态。

## 输出边界

固定输出太阳、月亮、水星、金星、火星、木星、土星，ASC、MC、DSC、IC，以及福点、精神点，包括：

- 黄经、星座、星座内度数、日运动速度与顺逆行；
- 主宫制宫位，并固定保留整宫制与以上升度起算的等宫制字段；
- 住所主、界主、角续果、到四轴距离；
- 同宫、六分、四分、三分、对冲与不相见，以及可计算的趋近／离开；
- 十二宫头与同星座行星组。
- 太阳真实地平高度、昼夜分支与临近地平线的时间敏感标记；
- 福点、精神点的黄经、宫位、住所主、界主、实际采用的公式与昼夜分支。

福点与精神点采用昼夜镜像公式：昼生福点为 `ASC + Moon - Sun`、精神点为 `ASC + Sun - Moon`，夜生互换。公式方向和昼夜依据必须随结果保存。临近日出或日落时仍按计算时刻输出，同时标记 `near_horizon`，提醒下游核对出生时间敏感性。

不输出解释专用主链、事项代理、尊贵分数、接纳互容、吉凶评价或事件判断。当前中立协议为 `chart-facts` schema v4。

## 失败处理

- 时间不明确：停止，不以正午代替。
- 时区、经纬度或恒星黄道岁差设置无效：指出缺失字段，不暗设默认值。
- 首次配置不存在：本成员先展示推荐的恒星黄道、Fagan–Bradley、埃及界、整宫制，询问是否更换，确认后保存。
- 新排盘口径与个人默认冲突：提示手动切换并停止本次创建。已存命盘的重算、显示快照及导出沿用该盘冻结事实，不能被后来修改的默认值覆盖。
- 校验失败：保留原输出供诊断，不交给解释 skill。
- 环境不可写：可输出到标准输出，但明确说明尚未保存。

## 提交前检查

- 本地时间、UTC、时区口径、坐标和方法设置是否完整？
- 是否只包含七颗可见行星、四轴、福点、精神点与中立盘面事实？
- 福点、精神点是否保存了公式、昼夜分支、住所主与界主；太阳临近地平线时是否保留敏感标记？
- 是否同时保留主宫制、整宫制和等宫制宫位字段？
- 是否运行 v4 输出校验器，并把计算与解释分开？
