# 公元1–2099年：历法与时间依据

出生日期归一化后的格里历年份支持0001–2099。前导零必须保留，如0001-06-01。公元前年份不作为出生输入；边界计算可能在证据中出现天文纪年0000（公元前1年），用于处理公元1年初的上一节、上一日或UT时刻，不是扩大输入范围。

支持范围指统一计算模型能够运行，不等于已复原两千年各朝代、各地区颁行的历法。

## 输入

- `calendar: solar`：格里历，1583年以前另须 `dateStyle: proleptic-gregorian`，说明使用逆推格里历。即使1583年以后，也应核实出生地是否仍用儒略历；不根据国家自动猜测改历日。
- `calendar: julian`：明确采用儒略历日期，按儒略历四年一闰换成格里历再计算，原始日期保留。转换后超出0001–2099会报错，例如儒略历公元1年最初两天落在格里历0000年，不在本次出生范围。
- `calendar: lunar`：中国农历ICU模型，必须填写闰月标记。1901年以前另须 `calendarBasis: icu-proleptic`；这只是明确接受统一农历模型反推，不冒充夏历、太初历等历史历法。朝代纪年或史料农历日期须先用可靠历表转换，不能仅补此标记就声称史料已核验。
- 1901年以前出生，须有 `timeSource` 说明当地时间依据；未知时辰也需说明日期所用地点／时制假设。历史IANA偏移本身不等于出生记录证据。资料不足须说明假设或保持候选，不能编造来源。
- 已有可靠记录给出精确历史偏移时，使用整数 `utcOffsetSeconds`（东正西负、绝对值小于86400）与 `timeSource`。此时优先该固定偏移，`timezone`仍保留地理IANA标签；节气日期浏览与当前日期定位也使用同一固定偏移，不再暗用现代时区。固定偏移会用于起运和推运时期，不自动追随当地后来改制。

弗洛伊德示例：`timezone: Europe/Prague`、`utcOffsetSeconds: 3464`，依据Astro-Databank的LST m14e26，等于UTC+00:57:44；出生地经度18°10′用于真太阳时换算，不能将时间标准经度误作出生地经度。

## 保留的默认

推荐默认仍为真太阳时、子初换日、春节子初换年、精确十二节换月、分钟起运折算至天及固定起点小运；已确认的五组可选算法同样适用于历史输入，定义见计算约定。古代节气按同一真太阳黄经规则反推，未增加平气法或历代颁行历法自定义。输出JSON记录历法模型、原输入、时间依据与限制。

1972年前将给定历史时制换成UT1近似，不把古代时间称为可追溯的原子时UTC。兼容字段仍用UTC命名，时间尺度说明随correction保留。古代ΔT模型和出生资料误差可能影响交节或时辰边界，不能以数值残差冒充史实精度。
