# 云端备份

在完整工作台的「设置 → 云端备份」启用。平时继续使用本地案例库；云端保存加密副本。

界面提供「复制指导提示词」，用户可粘贴给AI，按当前一步逐步设置。连接私有仓库、设置备份密码、选择备份频率等区域可分别展开和折叠；填写时按区域逐项进行。已有连接时先检查当前状态，不重复初始化。授权码、密码和恢复密钥由用户在页面自行填写。

## 首次连接

1. 在 GitHub 创建专用 **Private** 仓库，并添加 README。两套工作台可以用同一仓库，各自建立独立备份集合；只安装其中一套也能使用。
2. 创建 fine-grained personal access token，只选择这个仓库，`Contents` 设为 **Read and write**。在工作台填写「账号/仓库」和授权码，不需要 GitHub 登录密码。授权码过期后在管理中重新连接。
3. 设置至少10个字符的备份密码，选择间隔1–365天、时间及保留2–60份。默认每3天、09:00、保留12份。
4. 单独保存自动生成的恢复密钥，并粘贴一次确认。启用自动备份时才创建系统定时任务。

首次启用需要可选依赖；页面提供安装按钮，也可以由 AI 在工作台已有 Python 环境中运行：

```text
<工作台Python> -m pip install -r <可视化成员>/scripts/requirements-backup.txt
```

普通排盘与记录不需要这些可选组件。AI 协助连接时，让用户在页面输入授权码、密码和恢复密钥。

## 备份内容与存储

- 当前套件已经保存的出生资料、案例备注、分析、反馈、图层、笔记、历史记录和对应默认设置。
- 使用 SQLite 在线备份取得完整快照，包含已经提交到 WAL 的修改。临时 HTML、运行环境、程序副本、其他套件的档案不纳入。
- 八字的页面资源由已安装模板重新生成；占星案例引用的字体另存为共享加密资源包，同一套字体只上传一次，其他案例资源随快照保存。
- AES-256-GCM 分块加密，每次使用新的随机 nonce；密码通过 scrypt 包装随机密钥。密码与 GitHub 授权码不出现在云端文件或普通配置中。
- Windows 使用 DPAPI 保护本机密钥和授权码；macOS/Linux 使用系统钥匙串。没有可用钥匙串时不明文存储凭据，自动启用会给出具体提示；使用密码或恢复密钥下载恢复仍可进行。
- 加密文件放在私有仓库的独立草稿 Release 中，避免不断产生发布动态。服务器每次备份都核对仓库仍为私有。单份快照当前上限1.8GB。

自动任务每30分钟检查一次，按所选日期与时间决定是否备份。无需维持 AI、聊天或网页运行；电脑关闭时无法备份，开机登录后补做一次。没有数据变化就沿用原备份。断网、授权失效或上传中断保留旧副本，失败后逐步延长重试间隔；重新连接后可立即重试。

新副本大小与摘要校验成功后，才按保留数量清理旧快照。GitHub 未提供摘要时下载回读校验。共享字体包保留，避免删除仍被旧快照引用的资源。临时解压内容随操作结束清理；进程异常遗留的、带本模块标记的临时目录在下一次操作时清理。

## 恢复与忘记密码

「恢复备份」支持当前仓库或另行填写私有仓库及授权码。选择快照后，可用备份密码、恢复密钥或此电脑保存的密钥解锁。新电脑可以先恢复，不必先建立一套新备份设置。

恢复到独立目录后，先核对加密完整性、文件摘要、数据库、工作台类型及引用资源。原库保留。点击「接入这份恢复库」才修改当前套件的本机位置登记；可选择是否采用备份中的默认设置，再让 AI 重新打开工作台。

- 原电脑还能解锁：在管理中重设备份密码，不必记得旧密码。
- 有恢复密钥：可在另一台电脑恢复，再建立新的备份连接。
- 密码、恢复密钥及本机密钥都遗失：旧加密副本无法解锁；尚存的本地档案可用新密码重新开始备份。
- 密码或恢复密钥更换用于后续快照，旧快照仍使用原凭据，也可用对应本机密钥打开。更换密码不撤回别人已经取得的旧备份及密钥。

当前提供备份与恢复，不自动合并多台电脑的并行修改。阅读副本显示相同入口，并说明需在电脑端完整工作台连接；不能从手机聊天附件启动本机定时任务。

## AI 接口

使用已有运行环境与已经登记的对应案例库。此成员中的备份脚本自成一套，不依赖另一工作台。

```text
<工作台Python> <本成员>/scripts/cloud_backup.py --kind bazi status
<工作台Python> <本成员>/scripts/cloud_backup.py --kind bazi backup
<工作台Python> <本成员>/scripts/cloud_backup.py --kind bazi tick
```

占星使用 `--kind astrology`。显式 `--library`、`--settings` 优先；状态与凭据默认存放在用户目录 `.cgm-workbenches/backup/` 下，并按套件、案例库隔离。`status` 不返回凭据。`backup` 手动立即执行；`tick` 只在已启用、未暂停且到期时执行。

高级接口为 `action`，从标准输入接收 JSON，与页面共用实现：`prepare`、`confirm`、`update`、`pause`、`reconnect`、`change-password`、`rotate-recovery`、`confirm-recovery`、`snapshots`、`restore`、`adopt`、`reset`。用户确认接入后才调用 `adopt`；它保留原案例库及另一套位置登记。仅讨论备份时不自动上传档案或启用任务。

## 实现与验证依据

[SQLite 在线备份](https://www.sqlite.org/backup.html) · [GitHub 授权码](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) · [Release 文件接口](https://docs.github.com/en/rest/releases/assets) · [认证加密](https://cryptography.io/en/latest/hazmat/primitives/aead/)。

`tests/cloud-backup.py` 测试完整恢复、密码与恢复密钥、两套隔离、字体复用、断网重试、旧版本保留、并发、WAL、文件损坏和安全解压。`tests/cloud-backup-transport.py` 测试 GitHub 请求、分页、下载重定向、权限失效与截断。它们使用虚构数据和接口替身；真实私有仓库连接与 macOS/Linux 调度应在对应环境另行验证。


## 页面指导与折叠分组

顶部「复制指导提示词」提供按当前套件区分的 AI 逐步指导。初次连接的仓库与授权码、备份密码、备份频率及内容说明分别折叠；管理设置也逐组折叠。展开与折叠使用中文字样及加减号，控件等宽左对齐。必填项未填写时自动展开相应分组。授权码、密码、恢复密钥在对应页面输入，指导提示词不包含这些值。
