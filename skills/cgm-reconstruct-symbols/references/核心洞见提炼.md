# 核心洞见提炼

## 目的

在分析完材料后，尝试找到一个能够统摄整套符号系统的核心洞见：

> 这套体系把世界模拟成什么？它借助哪一种历史生活模型，把万事万物组织成可描述的对象？

核心洞见可以表现为“农耕循环”“城邦角色”“官僚案件流转”“皇权治理”“战场决策”等，但不得从预设菜单中选择，必须由材料推出。

## 核心洞见不是主题摘要

以下不算核心洞见：

- “这套体系研究吉凶”；
- “这套体系描述人生”；
- “它包含十二种不同作用”；
- 把所有符号释义重新排列一次。

真正的核心洞见应当揭示：

- 为什么这些符号会共同出现；
- 为什么它们采用这种分工；
- 为什么体系反复关注某些差异；
- 为什么它会忽略或压缩另一些现实；
- 为什么多套子系统必须这样协作。

## 推导步骤

### 一、寻找反复出现的历史场景

统计：

- 哪类现实角色最密集；
- 哪类行动过程最常成为规则原型；
- 哪些制度关系反复跨越不同领域；
- 什么样的事件最容易被完整拆解；
- 什么样的现实总是只能借用、附会或粗略表达。

### 二、寻找体系的默认观察者

追问：

- 这套体系像是谁在观察世界？
- 他需要做什么决定？
- 他能看到哪些信息？
- 哪些人或事只作为被管理对象出现？
- 什么结果对他最重要？

“皇帝模拟器”“城邦模拟器”等洞见，只有在观察位置和符号分工都支持时才成立。

### 三、提出多个竞争候选

至少提出两个能够解释材料的体系级候选，不要直接接受第一个漂亮比喻。

例如：

| 候选 | 能解释什么 | 解释不了什么 | 与另一候选的区别 |
|---|---|---|---|

### 四、检验解释压缩力

优先选择能用较少假设同时解释以下内容的候选：

1. 成员为何存在；
2. 成员如何分工；
3. 子系统如何协作；
4. 擅长领域；
5. 薄弱领域；
6. 历史使用场景。

不能因为一句话短，就认为压缩成功。压缩后仍须保留关键差异。

### 五、声明反证条件

每个核心洞见必须说明：

- 它排除哪种体系组织方式；
- 出现什么材料会推翻它；
- 哪些证据目前只构成部分支持；
- 它适用于哪个文本层或历史时期。

如果任何材料都能被比喻吸收，该洞见属于空泛修辞，必须拒绝。

## 核心洞见卡

| 字段 | 内容 |
|---|---|
| 一句话洞见 | 这套体系把世界模拟成什么 |
| 默认观察者 | 谁在使用这门语言看世界 |
| 基本场景 | 反复组织符号的历史生活模型 |
| 解释成员 | 为什么需要这些符号 |
| 解释协作 | 多套子系统如何分工 |
| 解释优势 | 为什么擅长某些领域 |
| 解释盲区 | 为什么不擅长某些领域 |
| 竞争候选 | 其他可能解释 |
| 反证条件 | 什么材料会推翻它 |
| 适用范围 | 哪个作者、文本层、时代或编者综合层 |
| 状态 | 可靠候选、局部候选、暂无可靠洞见 |

## 写作要求

- 一句话洞见应让普通读者立刻理解，但不能牺牲准确性。
- 可以使用“模拟器”“语言”“地图”等比喻，但随后必须解释其严格含义。
- 汇编文本可能拥有多个文本层洞见，以及一个编者综合层洞见。
- 核心洞见属于研究结论，不是宣传口号。
